# Design Document

## Overview 
This feature delivers a numerical evaluation engine for mathematical formulas generated by the LLM. The orchestrator will utilize this component to parse string-based expressions, optimize their unknown coefficients using Differential Evolution (DE) against TEP datasets, and obtain a unified fitness score based on RMSE and complexity penalties.

### Goals
- LLMから渡された文字列形式の数式を動的にJuliaの計算可能な関数へパースする。
- TEPデータセットを利用し、数式内の未知係数（a, b, c等）を差分進化法を用いて最適化する。
- RMSEとペナルティ（複雑さや物理制約違反）を合算した総合適応度（Fitness）を計算し、JSON形式で結果を返却する。

### Non-Goals
- 複数プロセスを用いた大規模並列分散計算エンジンの構築。
- Juliaから直接LLM APIへリクエストを送信する機能。
- データセットのダウンロード（`tep-data-loader`の役割）。

## Boundary Commitments

### This Spec Owns
- 数式文字列からJulia AST（抽象構文木）へのセキュアなパース処理と評価環境の提供。
- `BlackBoxOptim.jl`等を活用した差分進化法ベースの係数最適化ロジック。
- 指定された目的関数（RMSE計算）とペナルティ関数（ASTの深さやノード数に基づく）の評価計算。
- 外部プログラム（オーケストレーター）から呼び出し可能なCLIインターフェースおよびJSON入出力処理。

### Out of Boundary
- 最適化対象の「初期式」や「変異」の生成論理（LLMの役割）。
- DataFrameからのデータロードロジックの実装（`tep-data-loader`の関数に依存）。

### Allowed Dependencies
- `DataFrames.jl`
- `BlackBoxOptim.jl` （最適化バックエンドとして採用）
- `JSON.jl` （オーケストレーターとのデータ通信用）
- `tep-data-loader` モジュール（データ取得用）

### Revalidation Triggers
- オーケストレーター側で、評価リクエスト（JSON）のフォーマットや期待する返り値の形式が変更された場合。
- LLMが生成する数式に、現状サポートされていない新しい数学関数や特殊な演算子が含まれ始めた場合。

## Architecture

### Architecture Pattern & Boundary Map
本機能は、コマンドライン（CLI）から起動される単発のバッチ評価スクリプトおよびライブラリモジュール群として実装されます。 Pythonで書かれたオーケストレーターがサブプロセスとしてこのCLIスクリプトを呼び出し、標準入力/出力経由でJSONデータをやり取りします。

| Core Algorithm | BlackBoxOptim.jl | 係数の最適化（差分進化） | DEを含む複数のメタヒューリスティクスを提供 |

## Error Handling

### Error Categories and Responses
- **Parse Errors**: 入力された数式文字列が不正、またはホワイトリスト外の関数が含まれている場合。CLIは `status: error`, `error_type: ParseError` を出力し、終了コード `1` で終了する。
- **Optimization Divergence**: DE最適化がNaNに発散した場合やエラー終了した場合。 `status: error`, `error_type: OptimizationError` を出力する。
- **Data Load Errors**: `TEPDataLoader` 呼び出し時のファイル不在や変数名不一致。

## Testing Strategy
- Unit Tests:
  - `parser.jl`: 有効な文字列が関数に変換できること。不正な文字列が安全に弾かれること。
  - `fitness.jl`: 既知の入出力ペアに対して正しくRMSEが計算されること。ASTノード数に応じたペナルティが加算されること。
  - `optimizer.jl`: 単純な二次関数等を与え、最小値付近の係数が正しく探索できること。
- Integration Tests:
  - `cli.jl`: CLIに対してダミーのJSON入力をパイプで渡し、標準出力から正しいフォーマットのJSON結果（成功・失敗両方）がパースできることを検証する。
